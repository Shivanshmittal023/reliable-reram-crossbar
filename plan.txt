1. build a reram math simulator as a pytorch layer

A crossbar computes I = V · G, which is a matrix multiply. PyTorch does matrix multiplies natively.
- Store each weight as a conductance number G in a tensor. Compute x @ G as usual.

Bit-slicing is just splitting the integer weight into digits and doing one matmul per digit, then shift-and-add.
- Replace each nn.Linear with this layer, and the whole network runs as a "ReRAM chip" on the GPU.

2. svd 

 Before mapping, split each weight W into U · (ΣVᵀ) with k components. This gives two smaller matrices, so each layer becomes two crossbar layers back to back.
- The k components are the shared inner dimension. Each component r has an importance score I_r from gradients.
- Important components go into SLC cells (reliable). The rest go into MLC cells (dense but noisy). This is the tier tensor in the simulator.


3. Noise values of sigma 

Take values from papers. Papers that measure ReRAM report programming variation of roughly 2–10% of G_max. HyFlexPIM, Rasch et al. and ISAAC-style papers state the values they use. Cite them.
Sweep, do not fix one value. Run σ/G_max over 0–10% (   your Table 2). The result becomes accuracy versus noise, so no single guess matters much.

5. fault aware 

Fault rate: pick it from papers. Stuck-at rates of about 0.1–20% of cells are in your Table 2. Fresh chips are near the low end, worn chips near the high end. Sweep the range.
 Fault map: one random mask per simulated chip. Each cell is stuck at G_max or G_min with probability p. Optionally cluster the faults by row or column to mimic dead lines. Use a fixed seed so runs repeat.
- Effect in simulator: G[mask] = G_max or G_min, applied after programming. Whatever weight was meant for that cell is lost.
